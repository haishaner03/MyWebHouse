面试题与参考答案 共 20 题

1. C# 值类型和引用类型有什么区别？

答案：值类型变量直接保存数据，通常分配在栈或内联存储中；引用类型变量保存对象地址，实际对象在托管堆上。赋值时值类型复制数据，引用类型复制引用，因此两个变量可能指向同一个对象。
补充：struct、int 是常见值类型，class、数组、string 是引用类型。

2. ref、out、in 参数分别有什么用途？

答案：ref 要求调用前已初始化，可读可写；out 不要求调用前初始化，但方法必须赋值；in 按引用只读传递，适合避免大结构体复制。它们都改变了参数传递方式，但不能仅靠返回值类型重载。

3. 什么是装箱和拆箱？如何避免性能问题？

答案：把值类型转换为 object 或接口类型会发生装箱，运行时会在堆上创建对象并复制数据；拆箱则把对象取回指定值类型。频繁装箱会增加 GC 压力，可使用泛型集合（如 List<int>）和泛型方法避免。

4. virtual、override 和 new 的区别？

答案：virtual 声明可被子类重写的方法；override 表示子类真正参与多态重写；new 只是隐藏父类同名成员。当变量使用父类类型引用子类对象时，只有 override 会根据真实对象类型调用。

5. 委托和事件有什么区别？

答案：委托是类型安全的方法引用，可以被赋值、传参和直接调用；事件是对委托的封装，外部只能订阅和取消订阅，不能直接触发或覆盖事件。事件常用于解耦，例如 UI 监听数据层状态变化。

6. async/await 是否会自动创建新线程？

答案：不会。async/await 主要是把异步流程改写成易读形式，是否使用线程取决于任务来源。I/O 异步可以不占用线程等待；CPU 密集任务需要显式使用线程池等方式。Unity 主线程 API 仍必须在主线程调用。

7. Unity 中 Update、FixedUpdate、LateUpdate 如何选择？

答案：Update 随渲染帧执行，适合输入和普通逻辑；FixedUpdate 按固定时间步执行，适合 Rigidbody 物理；LateUpdate 在所有 Update 后执行，常用于相机跟随。不要在 FixedUpdate 中直接处理帧相关 UI。

8. Unity 协程的本质是什么？有什么限制？

答案：协程是由 Unity 驱动的迭代器状态机，每次 yield 暂停，之后在合适的帧继续执行。它不是后台线程，耗时计算仍会阻塞主线程；大量协程要注意生命周期、重复启动和对象销毁后的引用问题。

9. 为什么要使用对象池？

答案：频繁 Instantiate/Destroy 会带来 CPU 开销和 GC 抖动。对象池预先创建对象，使用时取出，结束后重置并回收，适合子弹、特效、敌人等高频重复对象。关键是完善重置逻辑，避免状态残留。

10. 如何定位 Unity 项目的性能瓶颈？

答案：先用 Profiler 判断 CPU、GPU、GC 或加载是否为瓶颈，再用 Frame Debugger、Memory Profiler 等工具缩小范围。常见优化包括减少 GC 分配、合批和降低 Overdraw、对象池、异步加载，以及避免每帧查找组件。

11. 接口和抽象类应该如何选择？

答案：抽象类适合表达“属于同一类事物”，可以共享字段、构造逻辑和部分实现；接口适合定义能力或契约，一个类可以实现多个接口。面试回答时要结合扩展性：变化频繁的能力通常更适合接口。

12. string 为什么是不可变类型？

答案：字符串不可变可以保证哈希值稳定，便于作为字典键，也让多线程共享更安全。连续拼接会创建多个临时对象，循环拼接应使用 StringBuilder；编译器会对常量字符串做驻留优化。

13. Dictionary 的查找为什么通常是 O(1)？

答案：Dictionary 基于哈希表，通过 key 的哈希值定位桶，再比较相等性找到元素，平均复杂度是 O(1)。哈希冲突会让查找退化，因此 key 必须稳定实现 Equals 和 GetHashCode。

14. LINQ 的延迟执行是什么？

答案：很多 LINQ 查询只构建表达式，不会立刻遍历数据，直到 ToList、First、foreach 等终结操作才执行。延迟执行适合组合查询，但要留意数据源变化和重复枚举带来的性能开销。

15. Awake、OnEnable、Start 的调用顺序是什么？

答案：对象加载时先调用 Awake；对象启用时调用 OnEnable；第一帧更新前调用 Start。Awake 适合自身初始化，OnEnable 适合注册事件，Start 适合依赖其他对象已完成初始化的逻辑。禁用对象不会调用 Start，直到首次启用。

16. 为什么不建议直接修改 Rigidbody 的 Transform？

答案：直接改 Transform 会绕过物理系统，可能造成穿透、抖动和碰撞检测异常。物理对象应在 FixedUpdate 中使用 MovePosition、AddForce 或设置速度，让引擎正确模拟运动。

17. Unity 中常见的 GC 分配来源有哪些？

答案：常见来源有每帧 new 对象、字符串拼接、装箱、临时数组、闭包、LINQ 和频繁 Instantiate。用 Profiler/GC Alloc 找到热点后，可通过缓存、非分配 API、对象池和预分配集合降低抖动。

18. 如何设计可维护的 UI 与业务代码？

答案：让 UI 负责展示和用户输入，业务层负责规则和状态，数据层负责存取；通过接口、事件或消息传递减少互相引用。这样便于单元测试，也能避免一个 MonoBehaviour 同时承担过多职责。

19. Resources、AssetBundle 和 Addressables 有什么区别？

答案：Resources 简单但不利于精细管理和热更新；AssetBundle 支持远程资源与版本控制，但需要自己处理依赖；Addressables 在 AssetBundle 之上提供地址化、依赖管理和异步加载，更适合中大型项目。

20. Git 中如何处理一次错误提交？

答案：已推送到共享分支的提交，优先使用 git revert 生成反向提交，保留历史；尚未共享的本地提交可以用 git reset 整理。提交前先看 diff，提交信息应说明改动目的，避免把构建产物和密钥加入仓库。
